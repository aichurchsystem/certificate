## 2. 넘기는 순서 (체크리스트)

1. **드라이브 폴더 소유권 이전** — `certificate-app` 폴더를 새 소유자에게 공유(편집자)한 뒤, 새 소유자가 `내 드라이브`로 이동.
2. **스프레드시트 소유권 이전** — `증명서-교인명단` → 소유권 이전(양도).
3. **Apps Script 프로젝트 소유권 이전** — 프로젝트 › 공유로 새 소유자를 편집자로 추가한 뒤 소유권 이전.
4. **새 소유자 계정으로 새 버전 재배포** — 배포 › 배포 관리 › 수정 › 새 버전 › 배포. **이때 새 배포 URL이 생깁니다.**
5. **앱 코드의 웹앱 주소 갱신** — `assets/app.js` 의 `var API_URL = ...` 한 줄을 새 주소로 바꾸고 커밋.
6. **키 새로 발급** — 40자 난수를 새로 만들어 `Code.gs` 의 `var KEY` 와 앱의 `관리자 › 드라이브 연결` 에 넣습니다. (기존 키는 폐기)
7. **GitHub 저장소 이전·Pages 재설정** — 저장소를 옮기면 Pages 주소가 바뀝니다. `Settings › Pages` 확인.
8. **시험 발급 1건** — 발급 → 드라이브 JPG → 발급대장 한 줄 → 발급 이력에 보이는지 확인하고, 시험 파일과 대장 줄은 지웁니다.

## 3. 바뀌는 것 · 주의

- **스크립트는 소유자 계정 권한으로 실행됩니다.** 소유권만 옮기고 재배포하지 않으면 예전 주인 계정으로 계속 돕니다. 4번이 반드시 필요합니다.
- **배포 액세스가 "모든 사용자"** 입니다. 주소와 키를 아는 사람은 명단·발급대장·공문을 읽고 쓸 수 있습니다. 키는 40자 난수 하나가 유일한 잠금장치입니다.
- **키는 공개 저장소에 넣지 않았습니다.** 앱은 이 기기 브라우저(localStorage)에만 키를 두고, 관리자 › 드라이브 연결에서 한 번 넣습니다. 기기를 바꾸면 다시 넣어야 합니다.
- **드라이브 권한 범위**는 구글 계정 전체 드라이브입니다(파일 하나로 좁힐 수 없음). 코드는 이 폴더들만 씁니다.
- **교인 개인정보**가 들어 있습니다: 이름·생년월일·주소·직분, 그리고 증명서 이미지. 넘길 때 접근 권한을 정리하고, 개인정보 처리 방침(수집 항목·보관 기간·파기)을 문서로 남기세요.
- 발급 파일과 공문 첨부는 **공유 링크를 만들지 않습니다.** 필요하면 소유자가 직접 공유해야 합니다.

## 4. 발급번호 규칙

- 형식: `접두어 + 연도-일련번호 + 호` (기본 `제2026-001호`). 연도는 발급 당일 연도가 자동으로 들어가고, 해가 바뀌면 그 해 1번부터 새로 시작합니다.
- 관리자 › **발급번호 설정**에서 접두어·시작번호·자릿수를 바꿉니다. 값은 시트 `설정` 탭에 저장됩니다.
- 번호는 **서버가 발급대장을 보고** 다음 번호를 계산합니다(`action:"next-no"`). 이미 대장에 있는 번호는 건너뜁니다.
- 실제 기록은 `action:"issue"` 한 번의 요청으로 **번호 확정 + 파일 저장 + 대장 한 줄** 이 함께 처리됩니다. 실패하면 파일도 지우고 번호를 쓰지 않습니다.
- 같은 번호·같은 이름으로 다시 보내면(재전송) 중복 저장하지 않고 기존 줄을 돌려줍니다.

## 5. 서버 동작(Apps Script)

| 액션 | 하는 일 |
|---|---|
| `issue` | 발급번호 확정 + `발급증명서` 폴더에 JPG 저장 + `발급대장` 한 줄 |
| `list` | 발급대장 읽기(이름·제목·번호 부분일치, 종류, 기간) + 엑셀(.xlsx) 내려받기 주소 |
| `file` | 발급 JPG를 base64로 (앱 미리보기, 공개 링크 없음) |
| `next-no` / `no-config` / `no-config-save` | 다음 번호 미리보기 / 규칙 조회 / 규칙 저장 |
| `notice-add` · `notice-update` · `notice-delete` · `notice-upload` · `notice-list` | 노회공문 등록·수정·소프트삭제(`사용여부=N`)·첨부 저장·목록 |
| `add` · `update` · `delete` · `bulk` | 교인 명단 |
| `verify` | **진위 확인 — 키 없이 공개.** `no`(자체번호)와 `inet`(문서확인번호)가 **같은 줄에서** 함께 맞을 때만 그 한 건의 최소 정보(마스킹한 성명·종류·제목·교회·발급일·취소 여부)를 돌려줌. 한 값만으로는 찾지 않고 목록·부분일치도 없음 |

- POST는 `Content-Type: text/plain;charset=utf-8` 로 JSON 본문을 보냅니다(`application/json` 은 사전 요청 때문에 실패).
- 모든 응답은 HTTP 200 + `{ok:true|false}` 입니다. `ok` 로 판단하세요.

## 6. 시트 구성

- `명단`: ID | 교회명 | 이름 | 생년월일 | 주소 | 직분 | 증명사진URL | 수정일 | 사용여부 | 교회주소 | 대표자 | 개척일(화면 표기: 기도처 시작일) | 설립일
- `발급대장`: 자체번호 | 문서번호 | 발급일자 | 증명서종류 | 제목 | 이름 | 생년월일 | 교회명 | 직분 | 노회공문번호 | 파일ID | 파일링크 | 지운여부 | 수정일 | **문서확인번호**(맨 끝)
- `노회공문`: ID | 문서번호 | 시행일자 | 공문일자 | 수신 | 제목 | 본문 | 일시 | 장소 | 대장 | 주요행사내용 | 노회장 | 서기 | 발신연락 | 파일ID | 파일링크 | 수정일 | 사용여부
- `설정`: noPrefix / noStart / noDigits

## 7. 문서 진위 확인 (2026-11-25 추가)

- 지면 오른쪽 아래 QR이 **확인 페이지 주소**를 담습니다: `verify.html?no=<자체번호>&inet=<문서확인번호>`. 크기는 30mm(앱 CSS `.p-qr`).
- 누가 확인하든 서버의 `verify` 액션만 부르고, 응답은 **한 건**뿐입니다. 생년월일·주소·직분·파일링크는 응답에 넣지 않습니다(개인정보).
- 확인 페이지는 `verify.html` + `assets/verify.js` + `assets/verify.css` 세 파일이고, 앱의 `lock.js`·서비스워커 캐시와 엮지 않았습니다(외부인에게 관리자 화면·명단이 보이면 안 되므로).
- **문서확인번호**는 앱이 발급할 때 만드는 4영문+9숫자(혼동 글자 제외) 값이고, `issue` 요청에 함께 실려 발급대장 맨 끝 칸에 남습니다.
- 2026-11-25 이전 발급분은 대장에 이 값이 없어 확인되지 않습니다. 같은 번호·이름으로 **다시 저장(재전송)** 하면 그 줄에 값이 채워져 확인되기 시작합니다.
